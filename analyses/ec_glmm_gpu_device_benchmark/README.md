# EC-GLMM CPU--GPU device benchmark

This benchmark runs the production gene-grouped scalar Laplace EC-GLMM with analytic multinomial derivatives, 12 posterior-mode Newton updates, implicit mode gradients, L-BFGS, production tolerances, and up to two retries. CPU and GPU runs use the same data, candidate order, initialization, and JAX 0.9.2 environment with 64-bit arithmetic. Both devices are on the same host, with two allocated Intel Xeon Gold 5115 CPU cores and one 16 GB NVIDIA V100 GPU.

The random mouse sample approximates the common case in which successive tests have different shapes and compilation cannot be reused. The grouped samples use existing dimension-stratified candidates ordered by gene, so multiple blocks from the same gene can reuse compiled objectives. The human singleton sample retains one block per gene from the grouped sample and is closer to the limited reuse in production, where 10,175 gene-and-pseudobulk groups contain 11,597 tests.

`results.tsv` reports model-fitting time measured by the runner after input loading and candidate construction. A speedup above one favors the GPU. The GPU provides no material end-to-end gain, with speedups of 0.685, 1.004, 1.015, and 0.986 across the four comparisons. All nested fits converge on both devices. Median absolute LRT differences are at most $3.0 \times 10^{-11}$; the largest difference is 0.0084 in the random mouse sample, where the devices take slightly different optimization trajectories.

The result does not support moving the scalar production fitter to GPU. GPU kernels reduce optimizer time for some grouped human shapes, but compilation, host-side SciPy control, device synchronization, and small per-fit matrices consume the gain. GPU acceleration remains useful only when many compatible fits can be batched, which is a different scheduler and was previously rejected as a common production replacement because it slowed the full human analysis and introduced local-optimum drift.
